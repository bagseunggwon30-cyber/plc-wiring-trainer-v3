이건 “결선 라이브러리” 하나로 해결되는 문제라기보다, **단자 좌표 캘리브레이션 + 최근접 단자 흡착 + 와이어 앵커 분리** 문제에 가까워. 지금 `index.html`도 단자를 `t.x / t.y` 기준으로 그리고, 같은 좌표에 `terminal-hit` 클릭 영역과 보이는 단자 원을 올리는 구조라서, 이미지 속 실제 나사 중심과 좌표가 조금만 틀어져도 네가 올린 MC-22b 이미지처럼 선 시작점이 옆으로 밀려 보일 수 있어. 현재 파일에는 `DEVICE_TERMINAL_DATA`처럼 장비별 단자 데이터를 따로 들고 가는 구조도 있어서, 여기에 “캘리브레이션 모드”를 붙이는 게 제일 현실적이야.

## 제일 추천하는 조합

**현재 HTML/SVG 구조를 유지한다면 `Moveable + RBush + SVG.js`가 제일 맞아.**

Moveable은 드래그, 리사이즈, 회전, 스냅 기능을 제공하고 SVG 요소도 지원하며 MIT 라이선스라서, “단자 캘리브레이션 모드” 만들기에 좋다. 즉 MC-22b 이미지를 띄우고, `1L1`, `3L2`, `5L3`, `A1`, `13`, `14`, `21`, `22` 같은 단자점을 실제 나사 중심으로 직접 끌어놓게 만들 수 있다. ([GitHub][1])

interact.js도 무료 오픈소스이고 snap/restriction modifier와 HTML/SVG 지원을 제공한다. Moveable이 “편집기 느낌의 핸들 UI”에 강하다면, interact.js는 지금 네 코드처럼 순수 HTML/SVG에서 드래그·스냅만 가볍게 붙이는 데 좋다. ([Interact.js][2])

RBush는 2D 점/사각형 공간 인덱싱용 R-tree 라이브러리라서, 모든 단자의 절대 좌표를 등록해두고 마우스 위치 주변 15~25px 박스 안에서 가장 가까운 단자를 빠르게 찾는 데 적합하다. 이걸 붙이면 사용자가 단자 원을 정확히 클릭하지 않아도 “가장 가까운 단자에 자석처럼 붙는” 결선이 된다. ([GitHub][3])

SVG.js는 의존성 없는 경량 SVG 조작 라이브러리이고 MIT 라이선스라서, 지금처럼 `document.createElementNS`가 많아지는 구조를 정리할 때 좋다. 특히 단자점, 라벨, 히트박스, 와이어, 고스트선, 선택박스를 객체처럼 다루기 쉬워진다. ([GitHub][4])

## 단자 위치 보정 전용으로 좋은 것

**Annotorious**는 이미지 위에 어노테이션을 올리는 JS/TypeScript 라이브러리다. 원래는 이미지 주석 도구지만, 네 경우에는 “MC-22b 이미지 위에 단자 중심을 찍고 `terminalId: x,y` JSON을 뽑는 도구”로 쓰면 딱 맞다. BSD 3-Clause 라이선스라 상업/개인 프로젝트에도 비교적 쓰기 편한 편이다. ([GitHub][5])

**CVAT**은 더 큰 규모의 이미지/비디오/3D 어노테이션 플랫폼이고 MIT 라이선스의 오픈소스 커뮤니티 버전이 있다. 단순 웹앱 안에 넣기엔 무겁지만, 장비 이미지 수십~수백 개를 “나사 중심 라벨링 데이터셋”으로 관리하려면 참고할 만하다. ([GitHub][6])

**OpenCV**는 Apache-2.0 라이선스의 대표적인 오픈소스 컴퓨터 비전 라이브러리다. 브라우저에서는 OpenCV.js 빌드를 써서 MC 이미지의 원형 나사 후보를 자동 검출하고, 사람이 마지막으로 보정하는 방식이 가능하다. 다만 처음부터 자동 검출에 올인하면 오탐이 많을 수 있어서, “자동 후보 표시 + 사람이 확정” 정도가 좋다. ([GitHub][7])

## 연결/와이어 라우팅 쪽 후보

**PathFinding.js**는 2D 그리드 기반 경로 탐색 라이브러리이고 A* 계열 알고리즘을 포함한다. 네 제어반 배선처럼 “장비 박스를 장애물로 보고, 배선덕트/그리드 위로 직각선을 우회”시키는 데 쓸 수 있다. MIT 라이선스지만 최신 릴리스가 오래된 편이라, 그대로 크게 의존하기보다는 A* 라우팅 참고용으로 쓰는 게 안전하다. ([GitHub][8]) ([GitHub][8])

**ELK.js**는 포트가 있는 노드-링크 다이어그램 자동 레이아웃에 강한 라이브러리다. “단자 위치 보정” 자체보다는, 나중에 회로도를 자동 정렬하거나 PLC/단자대/MC/EOCR 간 와이어를 포트 기반으로 정리할 때 쓸 수 있다. ELK 문서도 포트를 노드 경계의 명시적 부착점으로 다룬다고 설명한다. ([GitHub][9])

**diagram-js**는 웹에서 다이어그램을 표시하고 수정하기 위한 툴박스이고 MIT 라이선스다. BPMN 계열에서 많이 쓰이는 기반이라, 네 프로젝트를 “전기 제어반 도면 에디터”로 크게 재구축할 때는 후보가 될 수 있다. 다만 지금 HTML 한 파일 구조에 바로 얹기엔 Moveable/RBush보다 무겁다. ([GitHub][10])

**React Flow**는 React 기반 노드/엣지 에디터이고 MIT 오픈소스다. 핸들(handle)을 노드의 연결 지점으로 정의하고, 여러 핸들에 고유 id를 붙여 edge의 `sourceHandle`, `targetHandle`로 특정 연결점을 지정할 수 있다. 완전히 React로 갈아엎는다면 좋지만, 현재 순수 HTML/SVG 파일에 바로 추가하기엔 구조 변경이 크다. ([React Flow][11]) ([React Flow][12])

**JointJS**는 SVG 기반 다이어그램 라이브러리이고 anchors, connection points, ports, routers, connectors 같은 기능이 이미 있다. 전기 배선/SCADA/HMI/전자 설계 도구 쪽 사례도 언급되어 있어서 방향은 잘 맞지만, 라이선스가 MPL-2.0이고 구조가 커서 “기존 코드 보강”보다는 “새 버전 재구축” 후보로 보는 게 맞다. ([GitHub][13])

**jsPlumb Community Edition**은 웹앱 시각 연결용 라이브러리라 목적은 맞지만, 현재 커뮤니티 에디션 저장소가 “더 이상 업데이트를 받지 않는다”고 명시되어 있다. MIT/GPLv2 듀얼 라이선스라 참고는 가능하지만, 새 프로젝트 핵심 의존성으로 넣기엔 우선순위를 낮추는 게 좋다. ([GitHub][14])

## 네 상황에서 바로 넣어야 할 기능

지금 문제는 단자 하나를 `x,y` 한 점으로만 처리해서 생기는 경우가 많다. 실제로는 아래처럼 **4개 좌표를 분리**해야 한다.

```js
{
  id: 'A1',
  label: 'A1',
  pol: 'DC+',

  // 1) 화면에 보이는 나사 중심
  visual: { x: 210, y: 70 },

  // 2) 클릭/드래그 히트 영역 중심
  hit: { x: 210, y: 70, r: 18 },

  // 3) 와이어가 실제로 붙는 점
  anchor: { x: 214, y: 70 },

  // 4) 선이 장비 밖으로 빠져나가는 방향
  leadOut: { side: 'R', distance: 22 }
}
```

그러면 이미지상 원형 나사는 `visual`, 사용자가 클릭하기 쉬운 투명 영역은 `hit`, 선 시작점은 `anchor`, 선이 본체를 뚫지 않게 빠져나가는 지점은 `leadOut`으로 따로 계산할 수 있어.

## Codex에게 줄 작업 지시문

```md
현재 index.html은 장비별 terminals 배열의 t.x/t.y를 기준으로 보이는 단자 원, terminal-hit 클릭영역, 와이어 시작점을 모두 처리한다. 이 때문에 장비 이미지의 실제 나사 중심과 terminals 좌표가 어긋나면 결선 시작점이 틀어진다.

목표:
1. terminal 좌표를 visual/hit/anchor/leadOut으로 분리한다.
2. 캘리브레이션 모드를 추가한다.
   - 선택한 장비 이미지 위에 모든 terminal anchor를 표시한다.
   - 각 anchor는 드래그 가능해야 한다.
   - 화살표 키로 0.5px 또는 1px 단위 미세 이동 가능해야 한다.
   - 저장 시 DEVICE_TERMINAL_DATA 또는 별도 calibration JSON으로 반영한다.
3. RBush 기반 nearest-terminal snap을 추가한다.
   - 모든 단자의 절대 anchor 좌표를 RBush에 등록한다.
   - 결선 드래그 중 마우스 주변 20px 이내 단자를 검색한다.
   - 가장 가까운 단자가 있으면 고스트 와이어를 해당 단자로 스냅한다.
   - mouseup 시 정확히 terminal-hit 위가 아니어도 nearest terminal로 연결한다.
4. 이미지 중심 좌표와 앵커 좌표를 비교할 수 있도록 debug overlay를 추가한다.
   - visual point: 흰색 원
   - hit radius: 반투명 원
   - wire anchor: 주황 십자
   - leadOut point: 작은 파란 점
5. 기존 GOAL, 검증, netlist, 저장/불러오기 호환성은 유지한다.
6. 새 라이브러리는 우선 Moveable 또는 interact.js, RBush, SVG.js 중 최소 조합으로만 추가한다.
```

정리하면, **1순위는 Moveable 또는 interact.js로 단자 좌표 보정 모드**, **2순위는 RBush로 가까운 단자 자동 흡착**, **3순위는 visual/hit/anchor/leadOut 분리**야. React Flow나 JointJS는 좋아 보이지만 지금 파일을 살리는 방향에서는 과해.
