# v2.3 역할 기반 미션·제어회로 개선 기록

작성일: 2026-08-06
기준 프로젝트: `PLC_Wiring_Trainer_v2.2_Full.zip`
결과 버전: `2.3.0`

## 1. 이번 개선 범위

이번 작업은 v2.2에 이미 들어 있던 XBE/XBF 모듈과 전원·RS-485 검증을 유지하면서, 실제 제어회로 학습에서 가장 큰 오류를 만들던 다음 부분을 우선 교정했다.

- 같은 종류 장비 여러 대를 미션에서 서로 다른 역할로 식별
- 정·역운전, 자기유지, 전기 인터록 미션의 회로 구성 교정
- MDR-100을 사용하는 미션의 AC L/N 공급 경로 누락 방지
- XBC-DR32H 본체 전원과 입출력 단자 결선의 구분 강화
- EOCR-3DE/FDE 보호계전기 단자와 트립 동작 구현
- 시뮬레이션의 코일 스캔, 자기유지, 동시여자 차단, 인버터·모터 상태 계산 보완
- Electron 렌더러 보안 설정과 버전·패키징 설정 정리
- 문자열 존재 검사만이 아니라 실제 회로 상태를 계산하는 런타임 테스트 추가

이번 버전에서 새로운 GPT 장비 이미지를 추가 생성하지는 않았다. 기존 v2.2에 포함된 장비 이미지와 EOCR 이미지를 유지하고, 전기적 단자 ID와 상태 표시는 코드 오버레이로 처리했다.

## 3. 역할 기반 미션 장비 모델

기존 미션은 장비를 `type` 하나로만 찾았다. 따라서 MC 두 대, PB 세 대처럼 같은 타입이 여러 개 필요한 회로에서 첫 번째 장비만 반복 선택될 수 있었다.

v2.3은 다음과 같이 `type + role`을 함께 사용한다.

```js
{
  type: 'MC',
  role: 'forwardMC',
  label: '정회전 MC',
  interlockGroup: 'reversing-main'
}
```

핵심 처리 함수:

- `normalizeMissionDeviceSpec()`
- `missionNeededSpecs()`
- `deviceMatchesMissionSpec()`
- `findMissionDeviceId()`
- `applyMissionDeviceMetadata()`

기존 문자열 형식인 `needed:['MC']`도 계속 지원하므로 v2.2 미션 데이터와 하위 호환된다. 자동 배치, 자동 결선, 연결 검사, 미션 보고서가 모두 역할 정보를 사용한다.

## 4. 미션 교정

### g4 — iG5A 정·역운전

- 3상 MCCB → iG5A `R/S/T`
- iG5A `U/V/W` → 3상 모터
- 정회전 PB와 역회전 PB를 별도 인스턴스로 생성
- 각 PB의 NC 접점을 상대 방향 명령 회로에 직렬 삽입
- `CM-P1`은 정회전, `CM-P2`는 역회전으로 계산
- P1과 P2가 동시에 유효하면 인버터를 `CONFLICT` 상태로 표시하고 모터 운전을 차단

### g7 — 자기유지

표준 제어회로 순서로 재구성했다.

```text
+24V
 → 정지 PB NC
 → [운전 PB NO ∥ MC 보조 NO 13-14]
 → MC A1
 → MC A2
 → 0V
```

운전 표시등은 MC 코일과 병렬로 연결된다. 런타임 테스트에서 운전 PB를 놓아도 MC가 유지되고, 정지 PB를 누르면 MC가 탈락하는지 확인한다.

### g9 — 정·역 접촉기 인터록

- 정지 PB 1대, 정회전 PB 1대, 역회전 PB 1대
- 정회전 MC와 역회전 MC를 별도 역할로 배치
- 상대 MC의 NC 보조접점 `21-22`를 코일 회로에 직렬 삽입
- 각 MC의 NO 보조접점 `13-14`로 자기유지
- 같은 `interlockGroup`에서 두 코일이 동시에 계산되면 기존 유지 중인 한쪽만 유지하거나 둘 다 차단
- 동시여자 상태를 시뮬레이션 모니터와 장비 외곽선으로 표시

### g20 — EOCR 과부하 보호 DOL 기동

새로 추가한 미션이다.

```text
3상 주회로:
MCCB → MC 주접점 → EOCR R/S/T CT 관통부 → 모터

DC 제어회로:
+24V → 정지 NC → EOCR 95-96 NC
     → [운전 NO ∥ MC 13-14]
     → MC A1 → 0V
```

시뮬레이션 중 EOCR를 클릭하면 `TRIP/RESET`이 전환된다. TRIP 시 `95-96`이 열려 MC 코일이 탈락해야 한다.

## 5. EOCR-3DE/FDE 매뉴얼 반영

프로젝트에 포함된 `pdf/07_EOCR-3DE_FDE_Datasheet.pdf`의 단자표를 기준으로 다음 메타데이터를 적용했다.

| 기능 | 단자 |
|---|---|
| 제어 전원 | `A1(+)`, `A2` |
| 정상 시 닫힘/트립 시 열림 | `95-96` |
| 트립 시 닫힘 | `97-98` |
| 경보 출력 | `07-08` |
| CT 관통 도체 | `R-IN↔R-OUT`, `S-IN↔S-OUT`, `T-IN↔T-OUT` |

CT 관통 단자는 전기적으로 동일 도체로 계산하되, 화면에서는 입·출구를 별도 접속점으로 유지한다.

## 6. 공통 전원 프로필

DC 24V 장비를 사용하는데 MDR 입력이 없는 미션이 생기지 않도록 `MISSION_POWER_PROFILES`를 추가했다.

### `dc24`

```text
MCCB1P L' → MDR L
MCCB1P N' → MDR N
```

### `dc24-plc`

`dc24`를 포함하고 다음을 추가한다.

```text
MCCB1P L' → XBC 본체 L
MCCB1P N' → XBC 본체 N
```

프로필은 미션을 로드하기 전에 `needed`와 `checks`에 병합되며, 같은 연결이 중복 삽입되지 않도록 endpoint 키로 중복을 제거한다.

## 7. 시뮬레이션 개선

v2.3의 제어회로 계산은 직전 스캔의 접점 상태를 사용해 현재 스캔의 코일 상태를 계산하는 방식으로 보완됐다.

주요 상태:

- `SIM.coilState`
- `SIM.tripped`
- `SIM.interlockConflicts`
- `SIM.driveState`
- `SIM.motorState`

주요 처리:

1. 직전 코일 상태로 동적 접점 네트워크 계산
2. AC/DC 전원 source와 장비 전원 상태 계산
3. PLC I/O, RS-485, 아날로그·온도 채널 상태 계산
4. 현재 코일 후보 계산
5. 역할 기반 인터록 그룹 해석
6. 타이머·실린더·인버터·모터 상태 갱신
7. 장비 및 배선 다시 렌더링

지원되는 추가 동작:

- MC 보조접점에 의한 자기유지
- 정·역 MC 동시여자 차단
- iG5A `P1/P2` 정·역 명령 상태
- iG5A 출력에 연결된 모터의 운전·방향 상태
- EOCR 정상/트립 접점 전환
- 시뮬레이션 모니터의 TRIP, 인터록, 인버터, 모터 상태 표시

## 8. 배선 검증 정책

도어 기기에서 PLC나 모션 장비로 직접 연결한 경우를 미션 정책에 따라 구분한다.

- 일반 교육 미션: `quality` 경고
- `wiringPolicy:'terminal-block-required'`: `function` 오류

현재 단자대 경유를 필수로 하는 미션:

- `g-field`
- `g13`

기존의 AC/DC 단락, 전원쌍, I/O COM, RS-485 극성, 아날로그 +/- 및 RTD 3선 검사와 함께 동작한다. `danger` 또는 `function` 문제가 남으면 모든 단계가 연결되어도 미션 성공으로 처리하지 않는다.

## 9. 저장 형식과 호환성

- 프로젝트 스키마: `5`
- 미션 스키마: `2`
- 장비 인스턴스의 `role`, `instanceLabel`, `interlockGroup`, `interlockPriority`를 장비 데이터와 함께 저장
- 기존 `type`만 있는 저장 파일은 계속 로드 가능
- 기존 localStorage 키는 v2 이름을 유지하여 이전 작업을 잃지 않도록 함
- v2.2의 `MY-MD02 → XY-MD02`, `P24/P0V` 단자 마이그레이션을 유지

## 10. Electron 보안과 패키징

Electron 창은 다음 설정을 사용한다.

```js
contextIsolation: true
nodeIntegration: false
sandbox: true
webSecurity: true
allowRunningInsecureContent: false
```

추가 조치:

- `preload.js`를 통해 플랫폼·Electron/Chrome 버전 같은 읽기 전용 정보만 노출
- 새 창 열기 거부
- `file://` 이외의 임의 페이지 이동 차단
- HTML CSP 적용
- 앱·UI·패키지 버전을 `2.3.0`으로 통일
- 빌드 대상에 `preload.js`, `docs`, `pdf`, `README.md` 포함
- ASAR 패키징 활성화

## 11. 자동 검증 결과

최종 소스에서 다음 검사를 수행했다.

```text
inline JavaScript 구문 검사: 통과
main.js 구문 검사: 통과
preload.js 구문 검사: 통과
Node 자동 테스트: 40/40 통과
```

40개 테스트에는 다음 실제 상태 계산이 포함된다.

- 유효 L/N 입력에 따른 MDR·HMI·MD02·PLC 전원
- 차단기 개방 시 하류 AC/DC 차단
- MDR 무입력 시 DC 출력 비활성
- PLC 릴레이 출력과 램프 통전
- PT100·열전대 채널 완전 결선
- g7 자기유지와 정지 해제
- 정·역 MC 동시여자 차단
- iG5A 정·역방향과 모터 상태
- EOCR 트립에 따른 95-96 개방 및 MC 탈락
- 모든 미션의 장비·단자 endpoint 존재
- MDR 사용 미션의 AC 공급 경로
- XBC 사용 미션의 본체 L/N 공급 경로
- 전체 미션 자동 토폴로지의 AC/DC source 단락 여부
- 이미지 자산, 단자 ID, 좌표, 저장 마이그레이션

## 12. 확인하지 못한 범위

다음은 이 실행 환경의 제한으로 완료하지 못했다.

- Chromium/Electron GUI 전체 E2E: 실행 환경 정책이 브라우저 구동을 `ERR_BLOCKED_BY_ADMINISTRATOR`로 차단
- Windows용 EXE 빌드: 현재 실행 환경의 내부 npm 레지스트리에서 `electron@^32.0.0` 패키지를 가져오지 못해 의존성 설치와 EXE 빌드를 수행하지 못함
- 실제 XG5000, XP-Builder, GX Works 또는 실물 PLC 연동: 이번 버전은 그 연동 전 단계인 전기·미션·시뮬레이션 기반을 개선한 버전

따라서 제공 ZIP은 **검증된 소스 프로젝트**이며 Windows 실행 파일은 포함하지 않는다. 일반 인터넷이 가능한 Windows 환경에서 `npm install` 후 `npm start` 또는 `npm run build`로 확인해야 한다.
